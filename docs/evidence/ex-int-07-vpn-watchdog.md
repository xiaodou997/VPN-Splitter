# EX-INT-07：第三方 VPN 健康监测（watchdog 阶段一）真机证据

日期：2026-10-15。关联 [ADR-EX-INT-07](../adr/ADR-EX-INT-07-vpn-watchdog.md)。

## 范围

只读健康监测阶段一：显式开始/停止、固定间隔复用只读采集、状态迁移事件提示。**不自动暂停规则、不撤销路由、不修改网络。** 本证据不声称自动挂起能力（阶段二未实现）。

## 环境

- macOS 26 arm64；第三方 VPN：StrongVPN 在线（split-default 形态）。
- 预览 App：`dev.sh external-run` 临时构建（ad-hoc），未经签名/公证；未安装 Helper、未启用扩展、未写路由/DNS。

## 离线回归

- `dev.sh external-test` 全绿：ExternalCore Swift 测试 Debug + Release（含新增 `ExternalWatchdogTests` 12 例：初始在线/断开/重连/换隧道接口/物理路径变化/形态变化/物理丢失/读取失败不误报为掉线/不可用期间原因变化静默等）+ `tests/external` Python 合同 22 项（含新增 `test_watchdog_contract.py` 3 项：纯逻辑无采集/写入通道、模型显式启动且无 Helper/Flow 调用、UI 接线不破坏既有合同）。

## 真机执行（2026-10-14 晚首次，2026-10-15 复测）

1. 构建并打开预览 App，概览页出现「VPN 状态监测（只读）」区块。
2. 点击「开始监测」：状态变为「监测中 · 形态可识别」，详情显示物理 `en0 → 192.168.2.1`、隧道 `utun4（0/1 + 128/1）`；事件列表记录「开始监测：路由形态可识别」。持续约 1 分钟无额外事件（稳态无误报）。
3. USER_REPORTED：用户在 StrongVPN 客户端断开连接，数秒后重新连接。事件列表按时间倒序记录：
   - 「第三方 VPN 的隧道路由形态消失；分流语义可能已失效，建议核查」（vpnDisconnected）
   - 「路由形态恢复可识别（可能已换隧道接口）；建议重新检测并预览」（vpnReconnected）
4. 点击「停止监测」：状态显示「已停止 · 最后判定：形态可识别」，事件列表保留可见，按钮恢复为「开始监测」。
5. 全程未出现系统授权弹窗；未写路由、未改 DNS、未触碰 Helper/Flow。

## 真机发现并修复的问题

- 首次会话（2026-10-14 晚）跨睡眠：机器睡眠触发设计内的自动停止，但事件列表只在 `running == true` 时渲染，停止后事件不可见。已修复为停止后保留显示事件与最后判定，并于 2026-10-15 复测通过（第 4 步）。

## 边界与未验证

- 物理断网/切网（physicalPathLost/physicalPathChanged）、多隧道歧义等事件未做真机触发，仅有合成单测覆盖。
- 监测只做提示；检测到 VPN 异常后自动挂起分流为阶段二，需 route-trial 真机闭环后另行 ADR。
- 睡眠/唤醒自动停止为设计行为，非故障。
