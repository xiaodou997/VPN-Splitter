## 2. 源码审查发现：尚未修复

本次读取 `LocalDevApp.swift`、`Drafts.swift`、`LocalSession.swift`、现有 AppCore 测试及构建脚本。以下为源码审查，未进行新的 macOS GUI 复现或自动测试。

### LD-UI-01：编辑副本会覆盖随后修改的启用状态

`ProfilePane` 用独立的 `@State rule` 保存规则编辑副本。点击“编辑”将列表项复制进去；列表中的启用开关则直接保存到工作区。最后“保存修改”用整个编辑副本替换工作区中的规则，没有冲突检查或与最新状态同步。

复现路径：对一条已启用规则点“编辑” -> 在列表中禁用该规则 -> 在编辑区修改地址并保存。按当前赋值路径，编辑副本中仍为 true 的 `enabled` 会覆盖刚保存的 false。这会改变草稿中下一次预览的规则意图，但 LocalDev 不会把它应用到网络。

优先修复：让一个规则只有一个明确的编辑事务；编辑期间阻止对同一规则的旁路修改，或提供显式冲突处理。验收应覆盖启用、禁用两个方向，不能只测试最终地址。

### LD-UI-02：未保存输入在导航或切换编辑对象时没有保护

配置详情使用 `.id(profile.id)`，名称与规则输入保存在详情视图自己的 `@State`。选择另一份配置没有未保存检查；点击另一条规则的“编辑”直接替换编辑副本。没有保存、放弃、取消的导航保护。已保存到工作区的规则不受此项影响，风险针对尚未保存的输入。

SwiftUI 状态与视图身份关联的机制参见 Apple 的 [Demystify SwiftUI](https://developer.apple.com/videos/play/wwdc2021/10022/)。仅移除 `.id` 不是完整修复，会引入跨配置串用编辑内容的风险。

优先修复：使用可识别脏状态的编辑事务；切换配置、切换编辑对象及退出前保护未保存内容。失败保存不得关闭编辑器或丢弃输入。

### LD-UI-03：错误缺少规则定位与可操作说明

IP 解析错误退化为 `E_IPV4_INPUT`；其他编译错误只展示代码和内部 reason，没有把已有的 ruleID、suggestion 转成用户能定位的行号和说明。结构校验允许保存空或未支持的草稿，用户往往到预览阶段才看到错误。

改进：区分“可保存草稿”与“可预览策略”；输入处提示格式，列表行标注阻断原因，详细诊断保留错误码。不把原始配置或凭据回显到日志。

### LD-UI-04：开发测试控件与常用操作处于同一层级

模拟开始 / 停止、注入认证失败、规划能力预设、Include / Bypass、未实现规则类型都直接显示。名称 / 规则需要显式保存，模式 / 开关 / 排序立即保存；任何成功保存又会清掉旧预览并停止模拟。单条规则删除没有确认或撤销，而配置删除有确认。

这些不等于真实网络故障，但增加了理解成本和误操作风险。现有测试主要覆盖业务层，不能替代这些界面交互的验收。

## 3. 建议的下一批改动，不是已交付功能

先修 LD-UI-01 / 02，再简化主流程，然后继续既定的 LD-02 WireGuard 导入与凭据边界工作。

默认工作区集中在“选择策略 -> 编辑规则 -> 检查结果”。模式用“仅指定目标走 VPN / 除指定目标外走 VPN”表达，技术名放次级说明。IP / 网段规则编辑只突出目标、VPN / 直连和保存 / 取消；已有的未支持草稿仍须可见并明确标记，不能静默删除或跳过。

模拟故障、能力预设和合成示例入口放入开发工具；诊断先展示命中、冲突与下一步，技术路由展开查看。常驻保留“本地开发模式：不接管网络”，真实连接未实现的事实不能隐藏。

保存只表示本地草稿持久化，检查只表示纯逻辑预览，两者不等于应用网络设置。删除应提供撤销或明确确认。此建议不增加新网络后端，不改变 first-match 语义或 S0–S5 验收门槛，不恢复开发签名。
