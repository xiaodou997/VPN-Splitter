# S0 基线：历史资料复核与待验证项

日期：2026-09-23。任务：S0-01、S0-02、S0-04。状态：IN PROGRESS（历史资料已复核；当前真机场景未验收）。

## 来源与隐私

来源为项目讨论及用户先前提供的 VPN 前/后/差异快照。本轮离线读取了既有材料，并对原始快照中的 IPv4 路由段运行了本仓库的纯文本识别器；没有连接测试 Mac，也没有修改其网络。公开记录只保留不含用户地址、用户名、服务名称、厂商标识或凭据的结构事实，原始快照不入库。

历史时间、采集发生在宿主还是 VM、精确 macOS build、被测客户端与设备策略、当前网络是否相同，均不能仅由这些文本完整确定。以下不是“2026-09-23 真机重测通过”。

## 已观察的结构

| 观察 | 可以支持的结论 | 不能支持的结论 |
| --- | --- | --- |
| 连接后新增同一隧道/网关上的 0/1 与 128/1 | 存在已识别的 IPv4 全局路由模式 | 不证明可安全做 DIRECT 例外 |
| 原非隧道默认路径仍出现在表中 | 有待核实的原路径线索 | 不应直接把第一条 default 当可用物理网关 |
| 一个样本目的的 route get 结果由原接口变为隧道接口 | 系统查询结果变化 | 不证明真实 TCP/UDP 出口，也不排除接口绑定/过滤 |
| 连接前后 DNS 服务器列表与作用域状态变化 | DNS 必须单独验证，External 默认保留原配置 | 不证明 Split DNS 或域名分流已工作 |
| 同时有多个 utun、虚拟桥接及网络扩展记录 | 现场存在归因干扰，不能仅靠名称/数量选 VPN | 已安装/active 扩展不等于必然拦截被测流量 |
| 出现一条新增的原路径 host route | 可能是隧道控制连接保活路径，需核实 | 没有连接证据不能认定其目的就是 VPN Endpoint |

## 原工作流与已接受基线

已知项目要替代为了分流而维护的 VM + VPN + gost 组合，提供原生 Managed WireGuard/OpenVPN 和受限 External 路径。产品选择遵循 ADR-001，不重新开启默认模式等讨论。

历史配置线索还包含额外规则层、代理/TUN、DNS 转换及按应用等行为；这不证明该配置仍在使用，也不代表这些能力已纳入 v0.1。迁移必须区分“移除 VM/VPN 代理链”与“完整替代旧规则平台”。按应用、任意公网后缀发现等既定非目标不能被默认为已等价覆盖。

真实应用/域名/网络清单不公开。使用 tools/s0/scenario.local.template.md 在本机补齐目标代号与结果；若核心场景仍依赖非目标能力，则替代结论保持 BLOCKED，后续通过明确决策而不是隐瞒缺口解决。
