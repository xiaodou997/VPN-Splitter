# ADR-EX-INT-03A：External 本机规则方案与执行授权分离

日期：2026-09-28。状态：Accepted（本批数据/编辑边界）；不关闭 EX-INT-03 的 Helper 或 S4 执行验收。

## 决策

External 先把重复输入的 DIRECT 规则做成真正可保存、选择和编辑的本机文档。沿用 `external-run` 的现有应用，不再增加新的预览 App 或要求复制执行器路径使用规则管理。最多 16 套方案、每套 64 条 IPv4 规则，允许保存空方案/全部停用的方案，但这两种状态不能生成可执行预览。

每条规则保留 UUID、目标和启用状态；保留顺序，不静默去重或重排。批量输入先完整检查再一起加入；保存时用已有 PolicyCore IPv4 类型规范化地址和主机位，规范结果回显到编辑列表。停用项同样校验格式，只是不进入预览。

文档只保存 format、全局 revision、方案 ID/名称、规则及 selectedID。它不是权限、会话、路由所有权或网络快照；不保存网关、接口、DNS 观察、原始凭据或执行回执。未来 Helper 必须自行认证调用方并重新采集/验证，不能相信文件或 UUID 就允许写路由。

## 保存与编辑

通过 Foundation 的用户 Application Support 定位新目录 `io.github.xiaodou997.VPNSplitter.ExternalProfiles`，不迁移或覆盖 LocalDev 草稿、Keychain、`.local` 执行产物和 root 恢复记录。App 默认入口拒绝 root；测试可显式传入独立临时目录。目录 0700、文件和非删除锁 0600，文件读取有大小/类型/所有者/链接数检查，最终组件使用 no-follow。

保存遵循：校验候选 → 取得同目录锁 → 读取磁盘版本 → 拒绝旧编辑版本 → 写本次临时文件并 fsync → 再核对旧文档 → 原子改名 → 同步目录 → 读回完整比较。文件替换之后的失败明确报告 saveUncertain，要求重新载入，不自动重复覆盖。锁是遵守约定的同用户进程协调机制，不承诺防御任意同用户特权写入或提供系统级文件 CAS。标准 Application Support 父目录依赖 OS/用户管理，不宣称整个祖先链的特权隔离。

读取缺失文件才返回空列表；读取失败、损坏、不兼容格式、符号链接、硬链接或错误权限都不自动重置。现有文件版本过旧时保留编辑，禁止自动接受新 revision。重新载入/切换/新建前由操作者选择保留或放弃未保存编辑。删除需确认，成功后不自动选择其他方案；普通退出也询问未保存编辑，本地事务进行时拒绝退出。强制结束进程不保证保存未保存草稿。

选择本身需要保存 selectedID，因此也受同一 revision 检查；它不自动检测网络。规则/选择变化会取消旧检测并清除旧预览；预览仅针对已经保存、语法有效且至少有一条启用规则的方案。启动只自动读本机规则文件，仍不自动读取系统网络。
