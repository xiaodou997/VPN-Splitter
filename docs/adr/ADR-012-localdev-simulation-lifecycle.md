# ADR-012：LocalDev 的单一模拟生命周期与回调隔离

日期：2026-09-25。状态：Accepted（LD-03B 本地实现；不授予真实后端能力）。任务 LD-03、S4-04 前置；Refs #1。承接 ADR-007/008/011，不改变真实 Managed 必须签名授权、实际出口验收及原产品限制。

## 决策

LocalSession 内的 MockConnection 是唯一显示状态来源；独立 SimulationDriver 只调度模拟事件，不持有第二份产品连接状态。UI 不再自行用一个延迟 Task 直接设置成功。状态包括未开始、同步检查、连接中、模拟成功、停止中、已取消与失败；失败细分本地检查、模拟认证、超时和中断。

每次开始先用真实 PolicyPreview 编译当前完整策略，再绑定 profileID、随机 attempt ID 和完整 PlanContext。重复开始在编译前拒绝，不能清掉活跃预览或重置当前尝试。回调核对当前选择、计划上下文和尝试状态；连接成功只消费一次，连接中断只在模拟成功后接受。

取消/停止先撤销连接回调身份，再用独立停止 token 完成模拟确认。进入编辑、配置保存、选择变化、重新检查、凭据操作、手动环境变化和批准退出都使旧事件失效。无自动重试，用户手动重试才创建新尝试；不把旧规则偷偷降为 DIRECT。

## 时间和取消

Swift 任务取消是协作式的，不能仅凭 cancel() 证明排队中的完成回调不再执行，参见 [Swift Concurrency](https://docs.swift.org/swift-book/LanguageGuide/Concurrency.html)。因此驱动还有独立 operation ID，先使 ID 失效，再取消任务；即便调用方重复传入旧 attempt，也不会接受前次驱动的回调。

调度注入 SimulationScheduling。生产 LocalDev 使用 ContinuousClock 与可取消 Task.sleep；测试使用虚拟单调时钟和可强制交付的已取消回调。ContinuousClock 在系统睡眠中也继续计时，参见 [Swift Clock.continuous](https://docs.swift.org/latest/documentation/swift/clock/continuous/)。这只是计时选择，不代表已实现睡醒/切网探测。

驱动在同步检查完成后启动独立 3 秒截止定时器；正常/失败在 1 秒产生模拟结果，断线场景在成功后再等待 1 秒，停止确认演示为 250 毫秒。成功/认证回调也比较绝对截止时间，避免主执行器拥塞时过期成功先出队。任务取消不能替代状态隔离；虚拟调度必须保证异步且不早于请求延迟。

## 记录和边界

仅在内存保留 32 条固定事件，不包含可任意输入的文本、配置名称、目标或凭据引用。清空记录不改变状态；重启不恢复模拟。没有新的持久化版本、第三方依赖、网络或 Keychain 调用。

模拟不需要完整凭据，不能用它证明配置已经可连接。“模拟网络变化”不是系统通知订阅。同步规则检查不可抢占，真实协议调用的取消、扩展停机确认、停机超时、Keychain 授权与恢复仍需另行设计和真机证据。本次不把定时器替身包装成已完成的真实连接后端接口。

## 下一步与验收

先验证本批 Mac 交互并继续既有合成导入/凭据/参数清单，再推进真实后端接入准备；不继续用增加模拟场景替代真实数据面进度。首次真实 Managed 联调前恢复开发签名。LD-03 的本地生命周期子项有代码和离线回归，不关闭 S1–S5。

结果见 [本轮证据](../evidence/localdev-03b-lifecycle.md)。回撤使用正常后继提交，不改写 main，不清空 JSON、Keychain、锁文件或 .local。
