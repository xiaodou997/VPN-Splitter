# WG-INT-05：隧道与运行配置的绑定

本批在已有 WireGuard 构建候选上增加显式隧道描述符租约和运行配置核对，不增加模拟场景，也不增加新的工具安装要求。仍从 main 更新，不下载或手工应用补丁包。

## 更新入口保持不变

```sh
git switch main &&
git pull --ff-only &&
/bin/bash dev.sh engine --fetch
```

engine 自带环境检查；缺工具时停止，不自动安装或切换 Xcode。--fetch 明确允许固定公开源/模块下载，缓存齐全可省略；不运行 VPN 产物。仅使用界面继续执行 `dev.sh run`，不需要 Go；界面仍为 LD-03B。无需重跑 S0 人工路由实验或恢复签名。

## 实际变化

Adapter 不再扫描 fd 并挑第一个 utun。调用者必须提供已与该 Provider 对应的描述符及预期接口名；租约在副本上核对类型和名称，再把受保护的副本传给既有 Go 桥。测试使用普通 Pipe 和明确的检查替身，没有创建隧道。

绑定检查 Provider 实例、会话、配置版本、网络版本和凭据引用版本。接口/Peer/AllowedIPs 顺序和密钥等必须与快照一致；缺失当前版本、发现差异或明确失效后都不能恢复原绑定。仅把配置名称改为其他显示名称不改变协议快照。

网络设置生成使用独立配置副本，返回后再核对。设置完成后和协议调用前后再次检查；刚返回的引擎句柄若已过期，就在发布成功前释放。不因曾经检查通过就一直沿用旧版本。普通停止后需新会话，不在同一绑定上自动重连或热替换参数。

**名称核对不是 Provider 所有权证明，版本检查不是系统观察器。** 真实 fd 的可信获取、实际配置与策略投影、控制层触发停止、OS 设置撤销、签名与握手仍待实现/验证。当前候选没有可用的生产描述符提供者，正式 Provider 继续拒绝连接，不能拿链接探针的接口当成已接通的 VPN。

## 回归和结果

已有 `dev.sh engine-test` 会自动发现新增 Swift 与 Python 测试，不要求另记命令。新增完整上游参考文件的 hash 固定，原策略补丁、失败处理补丁及本批绑定补丁可顺序应用并与程序化变换逐字节比较。

本批本地执行结果见 [证据](evidence/wireguard-engine-05.md)。编译链接入口的成功字段仍是 `compile_link=PASS`、`artifact_execution=NOT_RUN`、`provider=NOT_LINKED`，不能解读为真实连接通过。新原生 socket 检查也尚未获得 Mac 结果。

用户策略/凭据版本与 .conf 不变，不访问 Keychain、不降低系统安全设置；失败日志继续保存在当次 .local/wireguard-engine/build.*。不要上传真实配置或全量日志，不通过删除数据/锁文件或强制 Git 覆盖来处理错误。
