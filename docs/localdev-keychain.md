## 导入与凭据保存

左侧“导入 WireGuard .conf”读取用户主动选择的本地文件。报告只展示网络结构，不显示任何密钥。新增策略默认不勾选“同时把凭据保存到本机 Keychain”：只点“仅保存结构”时仍是 LD-02A 的结构导入，不调用 Keychain。

勾选后明确点击“保存结构与凭据”，才调用系统 Keychain 保存接口私钥、Peer 公钥和可选预共享密钥。公开工作区只保存结构、随机引用及必要的待清理引用；不保存密钥、原 .conf、源路径或授权密码。新项保存后读回并比对完整数据，再关联到策略。系统访问被取消/拒绝或内容不符时不会回退明文，也不把新项关联为成功。

这是 LocalDev 独立 service 的文件型 macOS Keychain，用系统默认访问控制；没有 access group、iCloud 同步、Network Extension 共享或 security CLI。正式扩展的凭据访问须另验，不把当前记录视为扩展可直接使用。ad-hoc 重编译后的系统授权可能变化，这一点尚未实测；不要放宽 ACL、允许所有程序访问、关闭安全机制或上传授权材料来解决。

**已关联 Keychain 不代表本次读取成功、服务器认证成功或 VPN 连接成功。** 展开策略的 WireGuard 区域，点击“检查 Keychain 读取”才做本次读取/结构匹配检查；重启不自动访问或清理 Keychain。若条目缺失或无法读取，报告错误并保留策略，可从原文件重新导入。

原 `.conf` 必须继续保管。此实现不承诺 Swift String/Data 内存可靠零化，不属于 Secure Enclave 密钥方案，也不承诺锁屏即无法读取或 Keychain 文件不会被用户备份。

## 重新导入

策略“…”菜单或 WireGuard 展开区域选择“重新导入”，不会新建重复策略。保留策略 ID、名称、默认出口、规则 ID/顺序/内容；只替换配置结构与所选凭据关联。不会把 AllowedIPs 复制成用户规则，也不会扩张它来消除错误。新结构可能使旧规则不再通过检查，保存后须重新检查。

已有凭据时报告默认沿用保存凭据选项，仍需确认。新凭据使用全新引用而不是原地覆盖：新条目写入和读回验证通过、工作区新引用保存成功后，才尝试清理旧项。提交前失败保留旧结构和旧引用；提交后旧项清理失败则明确提示“新配置已保存，旧凭据清理未完成”。

重新导入时取消勾选意味着只保留新结构，并解除/尝试清理旧凭据；界面会说明，不能在新结构下继续偷偷使用旧密钥。取消整个报告不替换策略；失败后报告保留，可处理待清理项后重试。取消报告不取消已提交的清理记录。

## 移除、删除与待清理记录

菜单“仅移除凭据”保留结构、规则与名称；“移除导入结构”同时解除凭据，保留规则和名称；“删除策略”删除这一策略及规则。它们均需确认，均不修改原 .conf。单独删除规则不删除凭据。

顺序始终是先保存解除引用或策略删除，再尝试清理对应 Keychain 项。清理必须先读取验证 UUID / profile / ownership nonce，再按精确持久引用与 service/account 删除。缺失项可以确认清理完成；不可访问、取消、格式损坏或归属不符不触发盲删。不会扫描整个 Keychain，不按 service 批量清空。

失败会留下可见的“待清理 N 项”，全局区域即使没有策略也可见，导入报告内同样提供“重试清理”。这不表示已删除成功。重试只处理记录中的引用；重试清理完成后可以继续保存凭据。遇到归属/格式冲突请保留数据，不要通过清空 Keychain、删除 workspace 或手改引用绕过。

工作线程执行系统调用，期间阻止重复写入、编辑、导入与普通退出；仍可能需要响应系统授权。不要在处理中强制退出。启动不会自动处理残留项，用户检查并点击重试后才处理。

## 数据格式与恢复边界

工作区仍位于：

```text
~/Library/Application Support/VPN-Splitter-LocalDev/workspace.json
```

v1/v2 可以读取，普通启动不升级该 JSON。结构导入至少使用 v2；**首次凭据事务写入准备记录时升级 v3，即使后面的 Keychain 授权失败，工作区也可能已经是 v3**。v3 的引用不是密钥，但结构和名称仍可能敏感。不要把整个文件当作脱敏诊断上传。

旧程序会拒绝 v3；源码回退不等于数据回退，不手改版本号。不要在有待清理或活动凭据时恢复旧 JSON 备份或重置工作区，否则可能丢失引用并留下孤立条目。本批不枚举找回孤立项，也无自动降级。先保留原 .conf 和当前可读版本，再处理异常。

本版持有私有 `workspace.lock` 的 advisory flock，拒绝本版多实例并发写；锁文件保留是正常现象，退出会释放锁。旧程序不遵守这把锁，因此不能新旧同时运行。手工改 JSON / 同用户恶意竞态不在并发保证范围。

协调器的离线故障测试验证已提交记录的进程中断恢复次序，不构成 Keychain 与 JSON 的跨服务原子事务。临时文件同步和 rename 不提供完整目录 fsync / 掉电保证；断电、磁盘损坏、Keychain 服务极端中断和恢复旧备份未获验证。保留源文件，不把“可重试”理解成任何故障都不会遗失引用。

## 首轮 Mac 验收：只用合成数据

1. 导入 `tests/fixtures/wireguard/synthetic-ipv4.conf`。先取消，确认未增加策略；再导入并勾选保存凭据，确认“保存结构与凭据”。成功应提示读回校验通过，不显示真实 VPN 已连接。若系统没有出现授权弹窗，不要伪造“取消授权已验”。
2. 展开 WireGuard 区域点“检查 Keychain 读取”。成功后退出重开，再手动检查，应能读取或明确报告授权/缺失问题。顶部仍是本地开发模式，启动不自动弹凭据授权。
3. 改名为“合成凭据测试”，加 `10.9.0.0/16 → VPN`，检查 `10.9.4.5` 应匹配 peer-1。在同一策略选择重新导入 `synthetic-reimport.conf`；它使用不同测试密钥/地址/Endpoint，但相同 AllowedIPs。确认后应仍是一份策略，名称/规则保留，结构变为新样例；重新检查凭据与规则。
4. 测试“仅移除凭据”，先取消，再确认；结构/规则保留，凭据不再关联。重新导入并保存凭据后，用菜单删除这份合成策略。成功应无待清理项；失败应显示待清理并能在全局重试。不要用重要配置试删。
5. 若系统实际提示授权，取消一次：新策略不得显示凭据关联成功，旧策略不得被原地覆盖。报告应保留，可能有准备记录；明确重试清理后可再次确认保存。不通过改系统权限制造测试结果。
6. 检查处理中重复点保存、切换、编辑、Command-Q 应被阻止；处理完成后恢复。模拟仍只为模拟。窗口关闭/重开、Sheet/Dock 退出和重编译后的授权需在本机分别验证。

记录成功/失败、静态错误码和步骤即可，不发配置、密钥、workspace.json 或整个 .local。原生 Keychain 测试不会通过普通 swift test 自动执行；离线 tests 使用独立故障注入替身，不能当系统验收。
