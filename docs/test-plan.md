# v0.1 测试与验收计划

状态：Design Draft 1.0；2026-09-23。所有测试当前均为 NOT RUN。  
证据格式见 [evidence/README](evidence/README.md) 和 [模板](evidence/template.md)。

## 1. 测试原则

每项必须记录环境、前提、步骤、预期、观察、结论和证据。允许 PASS、FAIL、BLOCKED、NOT RUN、NOT APPLICABLE；后者需理由且不能豁免必需能力。

测试分纯逻辑、模拟状态机、协议集成、真实网络、签名发行五层。前一层通过不能替代后一层。文档与模板存在不代表任何联网试验已执行。

以新建连接为分流验证对象；既有 TCP/QUIC 会话另测行为但不承诺迁移。服务能访问不能证明选路正确；路由表符合预期也不能证明真实出口正确。

## 2. 真机环境与受控目标

最低必测：一台 macOS 26 arm64 真机、正常系统安全设置、一个 IPv4 物理网络；至少补一个真实双栈网络、Wi-Fi 与有线网络切换、一个干净安装用户环境。

记录精确 macOS build、CPU、Xcode/SDK/Swift/Go/C++、App commit、签名类型、上游 revision、原 VPN 客户端版本及连接方式。新 macOS 大版本需独立重测，不把 26 上的结论外推。

测试目标需用户/管理员授权：

| 目标 | 用途 | 证据 |
| --- | --- | --- |
| 一个 VPN 内部服务 | 证明 VPN 访问仍成立 | 服务端连接记录/受控响应、限定观察 |
| 一个公网直连服务 | 证明 DIRECT 例外成立 | 服务端观察的源地址或物理链路限定抓包 |
| 一个默认路径公网服务 | 防止只修好单个例外却破坏默认行为 | 独立服务端/链路证据 |
| 可控权威 DNS 与域名 | 测 TTL、CNAME、共享 IP、AAAA、错误响应 | 受控查询日志和测试记录 |

文档中的 .example、198.51.100.0/24 等为示例，不能拿它们当真实可访问测试目标。不要为了探测把企业名称发给未授权公共 DNS；不要默认把流量发往第三方 IP 查询服务。

## 3. S0 的最小操作规程

先记录“有 VM 的原工作流”和期望 DIRECT/VPN 的真实目标，明确哪些能力由 gost/VM 提供。检查是否可用本机配置替代认证，不提交秘密。

VPN 关闭、VPN 启用、例外应用后、撤销后分别采集只读基线。可在 Mac 上使用以下只读命令；原始输出可能包含敏感网络信息，公开前脱敏：

```sh
sw_vers
uname -m
ifconfig -a
netstat -rn -f inet
netstat -rn -f inet6
scutil --nwi
scutil --dns
```

对每个实际测试目的地址另查系统选路，并用受控连接观察实际出口。不能只使用 ping；至少一个实际 HTTP/TLS 或业务协议以及所需 UDP 场景。

所有写路由实验必须先明确真实物理网关、目标、撤销操作、授权和恢复入口，只操作一个受控目标。此文不提供可盲目粘贴的全局 route/PF 修改命令。

若网关不确定、多 VPN 歧义、存在强制策略或例外反复被覆盖，停止实验并保留诊断。S0 不尝试关闭企业安全机制。

## 4. 核心与规则测试

| ID | 场景 | 预期 | 关联需求 |
| --- | --- | --- | --- |
| T-P01 | IPv4 CIDR 规范化、边界、/0、/32、非法输入 | 结果确定，非法拒绝 | RULE-01 |
| T-P02 | 大网段在前、小网段在后及反序 | 满足 first-match，遮蔽可解释 | RULE-02 |
| T-P03 | 随机 CIDR 集合编译与参考解释器比较 | 所有抽样/边界地址结果等价 | RULE-02 |
| T-P04 | 相反域名动作共用同 IP | 新计划阻断，不按路由先后猜测 | RULE-03 |
| T-P05 | 域名与 CIDR 不可表达冲突 | 明确错误并关联规则 | RULE-03 |
| T-P06 | 相同动作多来源地址、来源过期 | 引用计数正确，不误删 | DNS-05 |
| T-P07 | 不支持的 REJECT、IPv6、External Include | 激活失败，不部分执行 | P-06、RULE-04 |
| T-P08 | 陈旧 generation/epoch 异步回调 | 丢弃，不覆盖新计划 | RULE-05、REL-02 |
| T-P09 | 规则、地址、编译路由超上限 | 阻断，不截断 | P-06 |
| T-P10 | Endpoint/DNS/LAN 与规则冲突 | 明示基础设施要求或阻断 | WG-04、DNS-02 |
| T-P11 | IDNA、大小写、末尾点、suffix 边界 | 确定语义，无错误后缀匹配 | RULE-01 |
| T-P12 | 版本升级/未知 schema/安全备份失败 | 拒绝或安全迁移，无秘密明文 | SEC-01、REL-01 |

T-P03 使用固定随机种子并保留失败输入。参考解释器不复用同一编译算法，避免实现和测试一起犯同样错误。

## 6. DNS 与域名测试

| ID | 场景 | 预期 | 关联需求 |
| --- | --- | --- | --- |
| T-D01 | Include 企业域 + 非企业域 | 可控查询证明 resolver 选择，数据路径分别验证 | DNS-01 |
| T-D02 | Bypass 下 matchDomains 和默认 resolver | 单独记录实际行为，UI 不冒称直连 DNS | DNS-03 |
| T-D03 | VPN DNS 不可达、企业域失败 | 本应用不自动公共回退，错误可见 | DNS-02、DNS-04 |
| T-D04 | DOMAIN A 轮换、TTL 到期、同名多地址 | 映射/路由按有效期更新，不无限持有 | DNS-05 |
| T-D05 | CNAME 链、零 TTL、NXDOMAIN、超时 | 原名归属正确；无法可靠管理时不新增 | DNS-05 |
| T-D06 | 先无冲突后解析成共享相反 IP | 运行态降级，派生路由安全撤回，明确通知 | RULE-03、FAIL-03 |
| T-D07 | DoH/DoT、自带 DNS、旧缓存、不同 CDN 结果 | 覆盖缺口可复现，不能显示精确保证 | DNS-05 |
| T-D08 | 后缀与固定 CIDR、子域返回范围外地址 | 显示网段扩大效应和范围外缺口 | RULE-01 |
| T-D09 | A+AAAA、IPv6-only、NAT64 | 拒绝强覆盖要求，显示实际未覆盖范围 | FAIL-02 |
| T-D10 | DNS 服务器地址与用户 DIRECT 规则冲突 | 阻断而非隐藏覆盖 | DNS-02 |
| T-D11 | DNS 更新跨睡眠、epoch 变化 | 旧记录不跨网络重放，重新验证 | REL-02 |
| T-D12 | DNS 返回本机/网关/Endpoint 等受保护地址 | 拒绝危险派生修改并报告 | SEC-02 |

S2 通过要求不是“所有流量都成功域名隔离”，而是定义的 DNS-derived 行为正确且已知局限能被证明和展示。无法获得可靠更新/有效期的数据源不能算自动 DOMAIN 通过。

## 10. 稳定性与性能基线

每个要公布支持的模式至少执行 10 次连接/断开、10 次重连、10 次睡眠唤醒、10 次网络切换；External 还需 App/Helper 各 10 次故障注入。每次保留自有对象前后差异；无歧义的正常清理不得有残留。刻意制造的归属歧义应按合同保留并报告，不以误删换取“零残留”。

连续运行至少 2 小时，覆盖 DNS 轮换和反复规则应用；记录 App/扩展/Helper 的 CPU、内存、文件/套接字数，检查泄漏与持续增长。资源异常不通过发布验收。

纯编译初始工程目标：固定 arm64 参考机，1,000 条规则、固定种子数据，预热 10 次、测量 100 次，P95 不超过 100 ms；不计 DNS 和网络操作。此为设计目标，不是当前测量结果。参考机器和调整理由在 S1/S2 固定。

隧道吞吐、延迟、丢包与无分流的同协议参考客户端比较，保留测量条件，不跨服务器/网络比较。绝对吞吐暂不写营销承诺；发现明显回退先分析桥接/MTU/配置，不靠关闭安全校验提速。

## 11. 发布阻断条件

以下任一成立则不能发布完整 v0.1：必要模式没有真机证据；规则被静默忽略；可重复错路由却显示正常；秘密泄露；误删第三方配置；未知配置执行脚本；签名仅在开发绕过环境有效；DNS-derived 声明范围与实现不符；强保证要求被错误接受；原工作流替代尚未验证却宣传已替代。

REJECT/完整 IPv6/严格域名隔离等非目标可缺失，但拒绝路径、提示和范围记录必须测试通过。External 始终按已测配置公布受限支持，不以一个厂商样本推断其他产品。

所有 S0–S5 阶段结论必须引用本测试 ID 与证据。实际执行者填写签署人/日期；不把计划作者自动当测试执行者。
