# LD-03A：编辑 WireGuard 配置参数

从 main 更新即可，无需补丁或 ZIP。先保存并完整退出旧 LocalDev，再执行 `git pull --ff-only` 与 `/bin/bash tools/localdev/build.sh run`。顶部版本为 LD-03A，仍显示“本地开发模式：不接管网络”。这不是可以连接的 VPN 版本。

## 操作

选择已经导入 WireGuard 的策略，展开 WireGuard 区域，点击“编辑参数”；策略菜单也有同名入口。空白策略需要先导入 `.conf`。本轮不直接编辑密钥。

| 字段 | 输入与边界 |
| --- | --- |
| 接口地址 Address | 用逗号分隔地址/前缀，保留主机位，不将接口地址变为网络地址 |
| DNS 地址 | 用逗号分隔 IP；不是域名分流，也不会修改系统 DNS。原搜索域只读保留 |
| 监听端口 ListenPort | 0–65535；空白表示未指定 |
| MTU | 本地导入子集为 576–65535；空白表示自动，实际执行与路径可用性尚未验证 |
| 每个 Peer 的 Endpoint | 主机:端口或 [IPv6]:端口；空白可保存，但缺失端点仍阻止当前配置检查 |
| PersistentKeepalive | 0–65535 秒，0/off 表示关闭，空白表示未指定 |

界面会列出修改的字段，允许展开核对将保存的结构及兼容性提示。语法错误不能保存，输入保留可修正。已有主机名/IPv6 或其他未覆盖情况不会在编辑中被静默删掉；格式合法的结构可以保存，但当前规划能力未支持的项目仍会阻止检查。

Peer 数量、身份和顺序、AllowedIPs、预共享密钥标记、密钥及搜索域均不在本轮编辑范围；修改这些内容需重新导入。保存不改策略名称、默认出口、规则 ID/顺序/动作，也不修改原 `.conf`。原文件仍需保管，应用内参数改动不会同步回原文件。

## 保存与凭据

仅结构策略：保存只更新工作区，不请求 Keychain，也不会自动补充凭据。

已关联凭据的策略：保存会按旧引用和旧结构读取 Keychain，在内部保留全部密钥创建新的随机引用记录，读回检查后发布新参数/新引用，最后清理旧项。旧项不是先删后建，也不就地覆盖。可能出现系统授权，请在本机处理；授权失败不回退为明文。

成功保存后需要重新点击“检查规则”；原来的检查结果及模拟状态不再有效。保存只是配置草稿已持久化，不代表路由、认证、DNS 或 VPN 生效。即便语法正确，新端点或 DNS 与规则冲突时，检查仍应拒绝。

## 失败与退出

保存前先记录恢复信息。Keychain 读取、授权、复制或读回失败时，原策略和凭据引用保留，未保存输入也保留；可能出现新的待清理记录。编辑窗口的“重试清理（不保存参数）”只清理记录内的条目，不保存输入；清理后重新点“保存参数”。如果原凭据本身仍不可读，需要解决本机访问问题或取消编辑后从原文件重新导入，不会自动移除旧凭据。

如果新参数已保存，但旧凭据清理失败，会明确显示“参数已保存；旧凭据清理待重试”；该失败不回滚已经关联的新参数。通过主窗口重试清理即可。归属不符或损坏的记录不会盲删，不能靠清空工作区、删除锁文件、批量删除 Keychain 或降低安全设置解决。

普通取消会在有未保存修改时询问是否放弃。参数编辑期间的退出提示只允许继续编辑或明确放弃；需要保存时先返回编辑窗口保存，再退出，避免退出回调中开启异步凭据写入。操作进行中不能重复保存、切换配置或普通退出；强制退出/掉电不保证保留内存输入。

工作区仍支持 v1/v2/v3，凭据 envelope 仍为 v1，本轮不引入格式升级。已有 v3 的回退限制不变；不恢复旧 JSON 来回退凭据引用。

## 合成验证清单（新版原生行为待验）

1. 导入 `tests/fixtures/wireguard/synthetic-ipv4.conf`，暂不勾选保存凭据。添加 `10.9.0.0/16 → VPN` 并检查。编辑参数把 MTU 从 1420 改为 1380、保活从 25 改为 30；保存后应保留名称/规则，旧检查清空，重新检查可通过。退出重开应保留新参数，原 .conf 不变。
2. 输入无效 MTU 或端点后保存，应保留输入且不修改策略；修正后可重试。编辑后取消或退出时确认未保存提示。
3. 把端点改为 `10.9.0.8:51820`，保存结构后检查应发现该端点与上述 VPN 规则冲突。编辑回原端点后重新检查。此操作不会联系端点。
4. Keychain 功能另用合成配置验证：先明确保存凭据，再编辑参数。授权成功后手动“检查 Keychain 读取”应匹配新结构；拒绝授权应保留旧配置并提示恢复。不要使用真实密钥作为首轮测试或上传 Keychain 输出。

本轮 Linux 替身测试不能代替第 4 项的系统授权/访问行为。布局已获用户反馈恢复正常，不等于所有新窗口、Keychain 或 VPN 已验收。
