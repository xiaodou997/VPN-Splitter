## 2. 产品目标

把“VPN 如何建立”与“哪些流量使用 VPN”分开，在 macOS 本机提供统一的分流配置、执行状态和诊断。用户可导入 WireGuard `.conf`、OpenVPN `.ovpn`，或保留现有官方/定制 VPN 客户端。

最终要替代的是为了分流而维护的“VM + VPN + gost”工作流，而不是承诺重新实现每个 VPN 厂商的登录、设备检查和安全策略。

典型主场景：默认 DIRECT，指定企业网段和企业 DNS 域走 VPN。次场景：默认 VPN，指定地址直连。配置能等价替代官方客户端时优先 Managed；必须保留官方客户端时使用受限 External 兼容模式。

成功必须由真实应用访问和实际出口验证，而不是仅由握手成功、出现 utun 或路由表变化判定。不能满足原场景时如实记录，不能宣布虚拟机已可移除。

## 4. 三种模式及其边界

### 4.1 Managed WireGuard

应用导入并安全保存配置，通过 Packet Tunnel System Extension 和 WireGuardKit 建立隧道。协议侧保留 peer、密钥、Endpoint、AllowedIPs；策略侧单独生成系统路由及 DNS 设置。

WireGuard 的 AllowedIPs 同时参与 peer 选择与接收地址校验，不能直接等同于用户的分流规则。WireGuardKit 当前设置生成器也把 AllowedIPs 转成 includedRoutes，因此需要一个有边界、可重放测试的适配点，而不是直接套用默认生成结果。证据与源码位置见[研究记录](research.md)。

### 4.2 Managed OpenVPN

优先研究 OpenVPN 3 Core，通过小范围 ObjC++/C 桥接在扩展内使用协议核心。导入、认证、服务器配置收集与最终系统网络设置应用分离。

服务器下发的默认路由不能越过本地策略；同时不能因为禁止全局路由就丢掉必要的隧道地址、DNS 或连接参数。CLI 的 route-nopull 仅是研究线索，不是完整的 Apple 嵌入方案。

### 4.3 External VPN

原客户端负责连接和认证，VPN-Splitter 仅识别当前网络状态并在验证兼容后增加有限 DIRECT 路由。默认不更改第三方 DNS、不删除第三方默认路由、不修改第三方进程或配置。

这是兼容性后端，不是 Apple 官方保证的任意第三方 VPN 扩展机制。Apple 明确建议 VPN 使用 Network Extension，而不是直接修改路由表；因此 External 按系统版本、网络环境、客户端构建和实际探测结果授予能力，不能只按厂商品牌宣称支持。[来源](https://developer.apple.com/videos/play/wwdc2025/234/)

“0/1 + 128/1”仅是路由模式线索，不足以排除过滤器、Kill Switch 或其他强制机制。无法可靠辨认物理路径、发现多隧道歧义、出现路由争用或强制策略时停止修改。

## 5. 统一规则，不统一虚假的能力承诺

```text
用户规则 + 配置 + 后端能力 + 当前网络快照
                    |
                 PolicyCore
        校验 / 冲突检查 / 编译 / 解释
                    |
                 PolicyPlan
     路由 + DNS + 基础设施例外 + 覆盖限制
                    |
         WireGuard / OpenVPN / External
                    |
           应用 -> 验证 -> 协调 -> 撤销
```

关键原则：

1. 规则无法表达或后端不支持，必须在应用前拒绝，不静默跳过。
2. DNS 解析器选择与数据连接选路分别展示。Split DNS 不等于域名精确分流。
3. 界面分别显示规则预期、系统观察和实际探测，不把其中一项冒充全部。
4. External 只修改可追踪的自有对象；无法证明安全撤销时报告冲突，不覆盖别人。
5. 新策略先编译和检查，再应用；运行时失效则降级状态，而不是继续显示全部生效。

首发域名语义明确收窄为：精确 DOMAIN 的 DNS-derived 地址路由，以及 DOMAIN-SUFFIX 与用户明确授权的固定 CIDR 集合组合。任意公网后缀的自动子域发现、DNS 劫持、Fake-IP、透明代理不进入 v0.1。详细限制和必测失败场景见[规则规范](policy-dns-spec.md)。

## 6. 用户使用流程

首次启动：展示平台检查及分流/防泄漏边界，选择模式；只在用到相应模式时申请扩展或 Helper 权限。

Managed：选择配置 -> 查看导入兼容性与敏感项 -> 选择 Include/Bypass 模板 -> 预览实际 CIDR 与 DNS 影响 -> 授权 -> 连接 -> 验证 -> 显示状态。

External：先由用户连接原 VPN -> 检测并显示候选路径 -> 确认受限兼容模式 -> 预览 DIRECT 例外 -> 必要时授权 Helper -> 应用并验证。无法确认网络身份时不靠猜测继续。

编辑规则时先保存草稿；“应用”生成新 generation。失败保留可证明仍有效的旧策略，否则撤销本会话修改并标记异常。显式退出默认结束本应用会话；关闭窗口不等于退出。

诊断支持输入一个域名或 IP，展示命中规则、DNS 选择、解析结果、实际编译路由、能力警告和可选连接探测。探测只针对用户确认的目标，不把访问记录上传公共服务。

## 7. 开发路径与阶段门槛

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| S0 | 真实场景说明、脱敏网络基线、External 最小兼容验证 | 双出口证据、撤销检查、场景价值结论 |
| S1 | 最小签名工程、PolicyCore 首批测试、WireGuard CIDR 隧道 | 扩展在真机可启动；协议与策略分离；Include/Bypass 验证 |
| S2 | DNS 策略、受限域名实现、冲突与 IPv6 警告 | DNS 默认路由差异、TTL、共享 IP、加密 DNS 等边界可复现 |
| S3 | OpenVPN 适配与配置兼容矩阵 | 真实认证成功；服务器 push 被正确审核；本地分流验证 |
| S4 | External Helper、状态协调、崩溃恢复 | 重连/睡醒/切网不抢路由；仅撤销自有更改；冲突停止 |
| S5 | 安装发行、回归报告、发布说明 | 所有强制测试通过；无凭据泄露；原工作流实际替代 |

S0 不是先开发完整 External 产品。它用于先发现“只有原客户端才可访问”的重大约束，再投入 Managed 工程。

阶段不按日历自动通过。上游源码可编译不等于功能通过，测试模板存在不等于测试执行。具体任务与门槛见[路线图](roadmap.md)。

## 8. 发布策略

开发预览可以只包含已验证模式，但必须标为相应范围的 preview，不能称为完整 v0.1。

完整 v0.1 的目标仍包含三条路径：Managed WireGuard、Managed OpenVPN、至少一个有证据的 External 路由兼容样本。External 和 DNS-derived 功能即使通过测试，仍明确标注受限/实验性能力。

如果 S2 不能在定义范围内提供 DOMAIN，或 External 不能满足任何目标样本，完整 v0.1 发布阻断。只能通过新的 ADR 明确调整范围，不能通过删除失败测试来宣告完成。

发布必须列出已测 macOS 精确构建、CPU、客户端/协议版本、IPv4 覆盖范围、已知限制和卸载方法。macOS 新大版本默认重新验证，不自动沿用旧版本兼容结论。

## 9. 首要风险和退出策略

| 风险 | 处理方式 |
| --- | --- |
| 官方客户端包含无法替代的认证/设备校验 | S0 提前识别；评估 External，不复制认证状态 |
| 路由型 External 被强制策略覆盖 | 停止修改并报告不支持；不尝试绕过 MDM/过滤器 |
| 域名共享 IP、缓存和解析路径不一致 | 明确 DNS-derived；已知冲突拒绝；严格需求需另做架构 ADR |
| WireGuardKit 设置生成与协议配置耦合 | 小范围补丁、版本固定、配置不变性测试 |
| OpenVPN 核心不能按要求嵌入/许可不合适 | S3 前审查；替代实现须 ADR，不启动协议重写 |
| 签名/授权阻碍真实运行 | S1 提前验证 Developer ID，不留到发布末期 |
| 断线/IPv6 产生未覆盖流量 | 用户可见范围警告；需要强保证的策略拒绝启用 |
| Helper 崩溃或路由身份歧义 | 持久化事务日志、有限租约、保守恢复、人工诊断 |
